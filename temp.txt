DCS GR(1) / Blocking — Optimization Candidates

  HIGH IMPACT

  1. canReachGoalOrMarkedIn / computeAttractor called per-state inside fixpoints

  GR1:findNewGoalsIn + propagateGoal call canReachGoalOrMarkedIn(s, C) for every state in C on each fixpoint iteration. Each call:
  - Iterates all of C to rebuild targets (calls isMarked per state)
  - Calls computeAttractor which scans region repeatedly

  Complexity: O(|C|² × |succ|) per fixpoint round. Fix: compute targets and attractor once per iteration, check membership for all states. Reduces to O(|C| ×
  |succ|).

  Relevant lines: OTFDirectedControledSyntesisGR1.java:577-599, 648-673, 677-688.

  ---
  2. computeAttractor uses naive "scan all" fixpoint

  while (changed) {
      changed = false;
      for (String s : region) { ... }  // re-scans entire region each round
  }
  Worst case O(|region|² × |succ|). Fix: worklist-based (backward BFS): start from newly added attractor states, propagate to predecessors only. Requires a
  reverse-adjacency index within succMap (already exists as parents). Reduces to O(|region| × |succ|).

  Relevant: GR1:648-673.

  ---
  3. getMaxLoop: unbounded forward BFS

  bfsForward(loopStart, null) — null limit means it traverses the entire explored graph from loopStart. Errors/goals are only filtered after the BFS.

  Fix: pass none as the BFS limit. States in goals/errors are pruned from the result anyway, so exploring them is wasted work. This also applies to
  DCSForPython.java:667.

  Relevant: GR1:530-535, DCSForPython.java:666-672.

  ---
  4. String-based state representation (largest structural gain)

  Every composite state is a heap-allocated String like "s0|s1|...|sN#phase". Hot-path costs:
  - splitState(nodeId) → regex split("\\|") on every call
  - StringBuilder construction for every successor state in exploreState
  - All HashMap lookups use String.hashCode() + .equals()

  Fix: intern states to integers on first encounter (Map<String, Integer> intern table). All internal maps (succMap, parents, goals, errors, none) become
  int-keyed. Eliminates regex splits and string allocations from the hot path. Major refactor but biggest throughput gain.

  ---
  MEDIUM IMPACT

  5. isMarked in GR1 parses phase string on every call

  phaseOf(nodeId) calls lastIndexOf('#') + Integer.parseInt() every invocation. Called inside every attractor loop iteration for every state in region.

  Fix: maintain a Map<String, Integer> nodePhaseCache populated in exploreState. Lookup instead of parse.

  Relevant: GR1:376-379, 418-434.

  ---
  6. controllerCanSatisfyAssumption inside isMarked without caching

  isMarked calls controllerCanSatisfyAssumption(nodeId, aCIdx) per assumption for every guarantee-phase state where the guarantee is not yet met. This iterates all
   successors of nodeId. Same state is re-checked on repeated calls (e.g., during attractor computation over a region).

  Fix: cache per (nodeId, assumptionIdx) → boolean. Cache is stable once a state is fully explored.

  Relevant: GR1:440-449.

  ---
  7. prunePending called on every getFrontier() invocation

  pending.removeIf(tr -> !none.contains(tr.from())) is an O(|pending|) scan. pending accumulates all unexpanded transitions; it grows large on bigger instances.

  Fix: lazy invalidation — maintain a Set<String> classifiedSources updated in promoteToGoals/promoteToErrors. Filter at pick time without modifying the list, or
  use a separate "active" count.

  Relevant: GR1:788-790, DCSForPython.java:567-569.

  ---
  8. pending.remove(index) is O(|pending|) on ArrayList

  Each expand() call removes from arbitrary index. For large frontiers this is expensive.

  Fix: swap-to-end before removal (pending.set(index, pending.get(pending.size()-1)); pending.remove(pending.size()-1)). Order in pending is irrelevant since the
  heuristic re-ranks on each pick.

  Relevant: GR1:303, DCSForPython.java:369.

  ---
  9. findNewGoalsIn double-nested fixpoint with per-state attractor

  Two nested while(changed) loops call safeInRegion and canReachGoalOrMarkedIn per state per iteration. The inner loop already collapses correctly but rebuilding
  attractor per-state is the bottleneck (see #1). Fixing #1 automatically fixes this.

  Relevant: GR1:577-599, DCSForPython.java:715-743.

  ---
  10. String.split("\\|", -1) in GR1 vs -1 vs bounded

  GR1's splitState uses -1 (unbounded split). DCSForPython correctly uses components.size(). A custom char-based split (scan for |) is ~3× faster than regex for
  short strings.

  Fix: hand-rolled splitOn('|', limit) helper.

  Relevant: GR1:391-393, DCSForPython.java:593-595.

  ---
  LOW IMPACT / STRUCTURAL

  11. propagateError fixpoint: restart-from-scratch on each change

  Iterator restarts from beginning of C when any state is promoted to error. Fix: use a predecessor worklist — when a state becomes an error, enqueue its none
  parents (from parents map) as candidates for isForcedToError.

  Relevant: GR1:691-703, DCSForPython.java:822-837.

  ---
  12. exploreState: build successor string even for eventually-illegal states

  exploreState builds the full StringBuilder destination string before any illegality check. If a component would go to ERROR, the string is built needlessly.

  Fix: detect ERROR destination inline during the component loop and break early.

  Relevant: GR1:495-526, DCSForPython.java:629-664.

  ---
  13. ancestorsNone and bfsBackward use LinkedHashSet for visited

  LinkedHashSet has constant overhead vs HashSet for visited.add() / visited.contains(). No iteration-order guarantee is needed here.

  Fix: replace with HashSet.

  Relevant: GR1:538-565, DCSForPython.java:674-703.

  ---
  14. canBeWinningLoop duplicates isMarked check with goals check

  Iterates loop twice: once for isMarked, once checking goal-successors. Could be merged into a single pass.

  Relevant: GR1:567-575, DCSForPython.java:705-713.
